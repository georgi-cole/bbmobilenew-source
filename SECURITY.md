# Security policy

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability or exposed secret.
Email the project maintainer directly with a concise description, reproduction
steps, and any affected URL or version. Do not include credentials, payment
details, or other sensitive personal data in the report.

## Supported releases

Only the current production release is supported with security fixes. Store
entitlements, API credentials, and purchase-verification secrets must remain
server-side and must never be committed to this repository or embedded in a
browser/mobile bundle.
